## 一、分析结论

本文件夹当前共有 **84张PNG**，已经全部分配永久来源编号 `V2L_0001`～`V2L_0084`：

- **71张运行候选**：构成新版陆地篇的基础UI、棋盘、数字、标记、错误反馈、七关生态、七关胜利展示、污染怪与机器人资产；
- **7张设计/色彩参考**：完整场景方案、尺寸图、棋盘布局图和色板；
- **6张历史输入参考**：原有陆地、海洋和天空棋盘参考图。

这里使用独立的 `V2L_####`，而没有直接续写正式 `ART_####`，原因是这些图片目前仍在 `docs/` 下，包含多组候选和概念图，尚未由用户确认进入游戏运行库。

当某张图片被确认并复制到 `assets/art/` 后：

1. 保留它原来的 `V2L_####` 来源编号；
2. 在Excel“对应正式ART编号”中记录映射；
3. 替换已有用途时沿用原 `ART_####`；
4. 新增运行用途时再由正式目录追加新的 `ART_####`。

因此它已经形成一套“新版陆地通用界面 + 基础棋盘 + 七关生态 + 双角色”的静态候选闭环，设计方向与原计划不同，但内部风格关系基本完整。

### 仍需处理的缺口

1. **按钮先采用程序状态反馈**：三个按钮目前都只有单一无字外观。本轮运行预览让 `normal / hover / pressed / focus` 共用同一贴图，并由Godot缩放反馈交互；用户确认整体方向后再决定是否补独立状态PNG。“开始/暂停按钮”图面当前只表现播放三角形。
2. **棋盘格基础贴图已经闭环**：未翻开、已翻开、污染三张纸面足够。悬停和键盘焦点继续由程序绘制不同颜色与粗细的虚线内框；扫描候选使用四角线框，扫描安全/危险结果使用扩散圆环，不需要增加对应PNG。接入新版贴图时应让hover复用基础格，避免继续混用旧风格悬停图。
3. **错误反馈需分层使用**：`V2L_0077` 是含史莱姆、被拔起小芽、红叉和碎土的大幅复合插画，适合触雷/误标后的反馈层，不应直接缩成34×34普通棋盘标记。
4. **棋盘数字已按用户要求接入**：陆地关卡使用生成的1–8图片，在格内按82%等比绘制，不再回退为Godot动态文字；最终缩放可读性由用户在真实游戏中确认。
5. **史莱姆需选版**：不服气、嘲笑各有三张候选。每组只能由用户选定一张，再统一所有状态的画布、中心、轮廓和底线。
6. **机器人需锁定基准**：左右视角包含候选与拆件；接入动画前要确定每个方向唯一基准，并统一组件比例、锚点、接缝和遮挡顺序。
7. **七关生态已经补齐，但需要统一规格**：第1–7关均已有健康/污染成对素材；第5关两张图的源尺寸不同，所有成对状态仍需统一画布、中心、底线与占位。断墙、蛛网、苔藓石、污染节点和Boss古树等独立机制素材仍未包含。
8. **两张棋盘纸Alpha需检查**：已翻开与污染棋盘纸目前是整幅半透明画布，需在Godot中确认叠色是否符合预期。
9. **大型胜利展示已补齐**：第1–7关均有独立的大幅生态世界图，可统一作为底部舞台胜利展示层；它们不替代棋盘内健康/污染成对生态。

## 六、维护命令

```bash
python tools/ver2_land_catalog.py discover
python tools/ver2_land_catalog.py export
python tools/ver2_land_catalog.py import
python tools/ver2_land_catalog.py validate
```

- `discover`：只为新增PNG追加新编号；可通过唯一SHA-256识别移动文件并保留编号；
- `export`：刷新尺寸、Alpha、文件大小和SHA-256并重建Excel；
- `import`：按 `V2L_####` 将Excel人工修改同步回JSON；
- `validate`：校验编号、路径、元数据和Excel一致性。

结构校验只确认清单数据，不代表视觉效果、34px可读性、布局、透明边缘或商用权已经通过。最终选择仍由用户完成。
