# 扫雷游戏 UI 布局与组件尺寸规范 v1.1

> 状态：**布局标注参考版（待 Godot 实机校核）**  
> 基准：用户确认的《棋盘操作区概念图.png》及随后确认方向的《游戏界面尺寸规格图.png》。  
> 适用：陆地、海洋、天空、宇宙四关卡。仅统一布局/尺寸与相对结构；不改变各关卡材质、配色和美术造型。  
> 单位：Godot 逻辑像素（px）；坐标原点为整个 1280×720 画布左上角，X 向右、Y 向下。  
> **来源注意**：下表为尺寸图所写的参考值，不是对图片重新测绘得到的工程精确值。示意图中有些尺寸、边界彼此不自洽，详见第 6 节；必须在锁版前实机核对。

## 1. 不可变的全局空间约束

| 项目 | 逻辑区域/尺寸 | 说明 |
|---|---|---|
| 游戏画布 | `(0,0) 1280×720` | 所有坐标的唯一原点 |
| 上方操作区 | `Y=0…500`，高 `500` | 上方无独立顶部信息栏；顶部计数器只是**覆盖在中央棋盘框上沿的独立悬浮 UI** |
| 底部动画舞台 | `(0,500) 1280×220` | 机器人、守护者、生态元素和特效仅在舞台区域运动，不得遮挡棋盘操作区域 |
| 两侧生态背景 | 左右均须留可见背景 | 不允许上方一体化 UI 铺满画布宽度 |
| 上方一体化视觉结构 | 中央棋盘框通过窄连接结构连接左右侧栏 | 不拆成三个视觉独立面板；内部素材允许 Godot 分层独立绘制 |
| 棋盘内容 | 动态渲染，最大 `13×13` | 本美术底框**不包含棋盘格、文字、数字、旗帜** |

## 3. 视觉与功能组合要求

### 3.1 一体化棋盘与便签

- 必须保留用户确认的原始概念图结构与形状比例，不可为迎合尺寸表而拉伸单个元素。
- 左右绿框是与中央棋盘相连的**一个整体视觉对象**；左右便签和图钉位于其上层。
- 中央棋盘开口必须真实透明，Godot 按关卡绘制其内部 `13×13` 或更小网格。
- 左侧月白/米白便签近似覆盖可用栏高；右侧便签较短（占右绿框上部约 2/3–3/4），右下角细小卷边，下部露出绿色框并容纳两个独立按钮。
- 每张便签仅一枚**绿色、金属质感、简洁**图钉；不在纸面添加额外叶片贴饰。

### 3.2 顶部独立组件

顶部布局层级（由下至上）：`中央棋盘框 → 绿色附着条 → 雷数/计时器框 → 红旗/秒表图标与动态数字 → 中央徽标`。相互位置按原图维持，不得把它们烘焙进棋盘底框。显示框本身为牛皮纸/再生纸材质，计数窗为深色纸面。

### 3.3 右侧按钮

- 两枚按钮：**开始/播放** 与 **设置**；均为独立素材，由 Godot 放置。
- 采用同一种温暖牛皮纸色、同一纸张压层结构，不使用粘土/塑料质感。
- 状态 `normal / hover / pressed / focus` 必须使用相同画布尺寸、中心、边界和基线；外部投影交给 Godot，素材本身不烘焙第二层落地影。

### 3.4 安全区与运动边界

- 角色、守护者和生态演出留在 `(0,500)–(1280,720)` 的舞台区，不得进入中央棋盘；顶端独立计数条不得遮挡棋盘点击区域。
- 背景留白属于生态视觉空间，不等于透明 PNG 必须连同背景一起绘制；UI 组件应独立分层输出真透明 RGBA。

## 4. 建议的 Godot 节点结构（不改变已确认视觉）

```text
GameRoot (Control, 1280×720)
├── EcosystemBackground (TextureRect)
├── UpperUI (Control, y: 0..500)
│   ├── BoardAndSidePanels (TextureRect, alpha)
│   ├── LeftNote + LeftGreenPin (optional separate sprites)
│   ├── RightNote + RightGreenPin (optional separate sprites)
│   ├── TopAttachmentStrip
│   ├── MineCounterFrame / MineIcon / MineCountLabel
│   ├── CenterEmblem
│   ├── TimerFrame / TimerIcon / TimerLabel
│   ├── StartButton (TextureButton)
│   ├── SettingsButton (TextureButton)
│   └── BoardCells (GridContainer / custom renderer, max 13×13)
└── BottomStage (Control, y: 500..720; clip animation bounds)
    ├── Robot
    ├── Guardian
    └── EcosystemAndEffects
```

## 5. 美术生产规格

- 源素材分辨率建议为最终目标显示大小的 2×（或经测试足够的倍率），**禁止因高分辨率而加入 UI 尺寸下不可读的细节**。
- 独立素材保存 `RGBA PNG`；不可用黑色背景代替透明。中央棋盘开口 alpha 必须为 0。
- 左上约 35° 柔和散射主光；仅保留纸层内部短小遮蔽，不包含外部落地影。
- 统一“温暖童话生态世界 + 手工再生纸板 + 分层剪纸 + 桌面微缩舞台 + 手写界面”。
- 配色以已确认的《配色修正记录》为准。本文件只锁 UI 结构尺寸，不覆盖配色或正式造型。

## 6. 必须在工程锁版前处理的标注冲突

1. **上方宽度留白**：若上方 UI 真为 `1000px` 宽且水平居中，则左右留白均应为 `(1280−1000)/2 = 140px`；尺寸示意图中的左右 `300px` 留白和 `X=980` 并不能与之同时成立。
2. **上方高度**：元素表把主框置于 `Y=130`、高 `440`，底至 `570`；两个按钮也至 `Y=572`。这会越过 `500px` 上区边界至少 70px。应整体等比缩放/平移组合，而**不是改动单个元素造型**，待用户批准具体变换后再发布工程绝对坐标。
3. **中央方形开口**：表中为 `316×394`；用户游戏需要最大 `13×13`，不能把这一个参考数字当作可用方形格区域。须从原始图片准确识别内框真实比例和 Alpha 有效矩形，设定正方形可绘制安全区，网格可在开口内居中，不必扭曲纸板框。
4. **顶部计数器与徽标**：其外廓应计入上方操作区的整体包围盒，不能只计算棋盘框尺寸。
5. **右侧纸张高度**：原文字约束是绿框可用高度的 2/3 至 3/4，尺寸图 `334/440≈75.9%` 略高于 3/4。应优先沿用已批准概念图外观；任何工程微调需实机评审。

**工程冻结原则**：在修正上述冲突之前，本文为**逐元素可追溯标注规范 v1.1（候选）**；不可宣称所有坐标已精确可用。后续如要生成严格落地的 `v1.2`，应先依据原图实际像素边界与 1000×500 容器等比例换算，再给用户确认完整对照图。
