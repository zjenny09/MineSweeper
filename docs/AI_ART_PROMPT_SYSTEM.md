# 《绿色扫雷》AI 美术提示词体系

> 适用版本：v0.7.0  
> 主要工具：ChatGPT Images  
> 用途：在不照搬现有来源不明素材的前提下，重新生成一套与当前游戏气质相符、整体性更强、适合 Godot UI 的正式美术资源。

---

## 1. 使用结论

当前游戏最有辨识度的视觉语言不是普通“卡通风”，而是：

**温暖童话生态世界 + 手工再生纸板 + 分层剪纸 + 桌面微缩舞台 + 手写界面。**

现有素材同时混合了摄影级纸模、黏土微缩景观、二维剪纸、程序图形和普通圆角 GUI。重新生成时不应逐张照抄，而应统一到以下目标：

> 精致但不过度写实的 2.5D 手工剪纸游戏美术。所有物体像由真实再生纸、棉纸和薄纸板裁切、压折、粘贴而成；轮廓清楚，层次有限，纸纤维可见，颜色温暖克制，适合缩小后作为游戏 UI。避免塑料、黏土、毛毡、金属和普通 3D 渲染感。

### 必须保留的现有特征

- 米白纸张、鼠尾草绿、阳光黄和生态青蓝；
- 可见纸纤维、裁切边、折痕、压纹和少量层叠厚度；
- 柔和、童话、友善的生态修复主题；
- 中央棋盘最大、左右窄纸卡、角色沿底边陈列的三栏布局；
- 健康与污染两种清楚但不恐怖的状态；
- 陆地、海洋、天空和宇宙有明确章节色彩差异；
- 小芽机器人、污染怪和生态主体使用同一种纸艺渲染程度。

### 需要统一和改善的部分

- 不再混用黏土模型、塑料玩具、写实摄影与二维卡通描边；
- 不生成带背景的“透明素材”，不保留白边、黑边或棋盘格底图；
- 不让角色图片自带巨大落地影，阴影统一交给 Godot；
- 不让 AI 把中文、按钮文字、数字和状态文字画进图片；
- 不把多个操作按钮做成完全相同的无图标圆片；
- 不分别自由生成状态图，必须由同一张基准图编辑得到；
- 天空和宇宙需要形成完整的章节专属 UI，而不是继续复用其他章节按钮。

## 2. 合规与参考图规则

1. 不要将版权和商用许可不明确的旧豆包图片直接上传给 ChatGPT，要求它“照着重画”。
2. 本文已将当前风格转写为通用的文字规范，第一批新素材应只根据文字生成。
3. 第一批中确认一张全新的“风格基准图”和一张全新的“小芽机器人设定图”。
4. 后续只上传这些由当前商用账户新生成、权利链清楚的基准图作为一致性参考。
5. 提示词中不得出现具体在世艺术家、知名动画、游戏、影视 IP 或品牌名称。
6. 保存订阅订单、生成日期、完整提示词、下载原图及当日服务条款截图。

## 3. 生产规格

### 3.1 游戏基准

- 逻辑画布：1280×720；
- 全屏背景母版：2560×1440 或更高的 16:9；
- 桌面章节背景可继续使用：2848×1600；
- 独立角色、生态主体：1024×1024 RGBA；
- 大型生态主体：1536×1024 RGBA；
- 小图标、标记、棋盘格：512×512 RGBA；
- 对话框：1200×436 RGBA，最终缩至 600×218；
- 按钮底板：先生成 1024×256 或 512×512，再裁切和制作 9-slice；
- 所有状态组必须使用完全相同的画布、中心、基线、缩放和透明边界。

### 3.2 UI 安全要求

- 独立素材：真正透明背景；
- 不生成文字、字母、数字、Logo、签名、水印；
- 不生成棋盘格透明背景图案；
- 主体四周至少留 8% 安全边距；
- 小图标缩至 48–96px 后仍须一眼可辨；
- 不依靠极细纹理和微小零件传达状态；
- 外部投影默认关闭，由 Godot 统一绘制；
- 允许纸片内部有轻微层间遮蔽，但不能形成第二个落地影；
- 同组 normal / hover / pressed / focus 状态不得改变轮廓和占位。

### 3.3 固定光照

除全屏背景外，所有独立素材统一采用：

- 柔和工作室散射光；
- 主光从左上方约 35° 入射；
- 纸层内部只产生短而柔和的右下遮蔽；
- 无强烈高光、无镜面反射、无电影级景深；
- 正交或近似正交视角，避免夸张透视。

## 22. 按钮状态生产方法

AI 最容易在多状态按钮上产生尺寸漂移。必须按以下顺序：

1. 只生成 normal；
2. 裁切为统一画布；
3. 将 normal 重新上传；
4. 使用“仅编辑颜色与纸层压下程度，严禁改变轮廓”的指令；
5. 分别生成 hover、pressed、focus、disabled；
6. 在图像编辑软件中对齐检查；
7. 图标与底板分开保存；
8. Godot 中用 StyleBoxTexture 或 9-slice 组合。

统一编辑提示词：

```text
这是同一游戏按钮的状态编辑任务。严格锁定原图画布、像素边界、外轮廓、圆角、纸纤维、中心和每一层纸片的位置，不得重新设计，不得缩放，不得旋转，不得增删零件。只执行以下变化：[填写状态变化]。输出透明背景，不生成文字、图标或外部阴影。
```

## 23. 健康 / 失败状态生产方法

生态主体、角色和标记都遵循：

- healthy 先生成并批准；
- failed 只能基于 healthy 编辑；
- 主体数量、轮廓、镜头、画布、中心和底线必须锁定；
- 失败状态依靠下垂、失色、灰紫污染纸片和表情表达；
- 不使用死亡、腐烂、骨血、真实污水或惊悚元素；
- 不在失败图里擅自添加新角色和背景。

## 26. ChatGPT 实际操作顺序

### 阶段 A：确定唯一画风

1. 新建一个专用对话；
2. 粘贴全局母提示词；
3. 生成总风格板；
4. 生成 UI 缩略测试板；
5. 只选择一套作为正式标准；
6. 不满意就修改风格板，不要先批量生产。

### 阶段 B：锁定角色和基础 UI

1. 生成小芽机器人设定图；
2. 生成污染怪设定图；
3. 生成信息纸卡、对话框和按钮 normal；
4. 把这些新图保存为 `style_reference`；
5. 后续每个新对话都附上这些合法的新基准图。

### 阶段 C：先做一关完整垂直切片

建议先重做第 1 关所需的：

- 陆地背景；
- 中央棋盘框；
- 左右纸卡；
- 一套方格状态；
- 小芽标记和污染怪；
- 第 1 关健康 / 失败生态；
- 暂停、重开和扫描图标。

放进 Godot 由玩家实际查看。只有这一关整体通过后，再批量扩展。

### 阶段 D：按章节批量生成

顺序建议：陆地 → 海洋 → 天空 → 宇宙。每次只处理一个类别，不要在同一轮混合背景、角色、按钮和棋盘格。

### 阶段 E：状态与技术清理

1. 从 approved normal 图编辑其他状态；
2. 统一裁切、画布和基线；
3. 检查透明边；
4. 生成 1x / 2x 运行版本；
5. 进入 Godot 人工检查，不以单张图片预览代替游戏内判断。

## 28. 每张素材的验收清单

### 视觉

- [ ] 一眼能看出手工纸与分层剪纸；
- [ ] 不像黏土、塑料、毛毡或普通 3D 模型；
- [ ] 与小芽机器人和污染怪的细节等级一致；
- [ ] 缩至实际 UI 尺寸仍可辨认；
- [ ] 章节色彩明确，但仍属于同一个游戏；
- [ ] 没有文字、乱码、Logo、签名或水印。

### 技术

- [ ] RGBA 真透明；
- [ ] 无白底、黑底和透明棋盘格；
- [ ] 无锯齿、白边、黑边和背景残色；
- [ ] 无外部落地影；
- [ ] 同组素材画布、中心、底线和占位一致；
- [ ] 在白、黑、洋红及章节背景上检查过透明边；
- [ ] 有原始高分辨率和实际运行尺寸两份；
- [ ] 文件名、目录和用途清楚。

### UI

- [ ] 文字由 Godot 排版，没有烘焙在图片中；
- [ ] 按钮图标与底板分层；
- [ ] hover、focus、pressed 和 disabled 可明显区分；
- [ ] 状态不只依赖颜色，也有轮廓或符号差异；
- [ ] 1280×720、窗口、最大化和无边框全屏均未遮挡；
- [ ] 底部生态、垃圾、角色和重要装饰没有被裁掉。

### 合规留档

- [ ] 使用明确允许商用的账户和套餐生成；
- [ ] 保存提示词、生成日期和原始文件；
- [ ] 保存订单与当日条款；
- [ ] 未使用知名 IP、品牌、真人或具体艺术家名称；
- [ ] 未将权利不明的旧图作为图生图输入。

## 29. 最重要的执行原则

1. **先锁定风格板，再生成整套素材。**
2. **先完成一关垂直切片，再扩展四章。**
3. **新生成的合法基准图，才是后续一致性参考。**
4. **健康图生成一次，失败图只做受控编辑。**
5. **按钮 normal 生成一次，其他状态只做受控编辑。**
6. **背景负责气氛，UI 负责信息，不能互相争夺视觉焦点。**
7. **所有文字、数字、连线和高频动态状态尽量由 Godot 绘制。**
8. **AI 输出是素材初稿，不是自动通过的最终资源。**
9. **不使用粗糙自动抠图和临时合成阴影作为正式美术。**
10. **最终视觉是否合格，以真实游戏中的人工检查为准。**
